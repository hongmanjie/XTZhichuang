# 实施记录与 Linux 部署说明

更新日期：2026-10-29。本文件记录当前实际完成的能力和限制，后续每次扩大部署范围时应重新验收。

## 当前已实现

- AI 素材场使用 MiniMax-H3，支持文字、首帧、尾帧以及首尾帧。页面支持 4、8、15、30、60 秒；15 秒及以上由后台自动规划镜头、逐段生成、提取上一段结尾画面衔接并用 FFmpeg 合成，不要求用户操作画布。60 秒最多需要 8 次视频模型调用，耗时和成本随任务量增加。
- 长视频规划借鉴本机 XT 工作台的商品短片和分镜方法，描述镜头起止状态、动作、运镜、环境音以及统一视觉风格。当前规划模型只读取用户文字和是否提供首尾帧，不具备识图能力；首尾帧由 H3 实际接收，商品内容理解和外观保真仍受模型限制。
- 单段模型帧数、画幅按网关约束校验；视频时长和尺寸由 FFprobe 读取。4 秒请求从模型返回结果调整时长；有尾帧时保留结尾再调整时长。
- 有持久化任务、点数预留与失败退回；长视频各段保存请求和上游任务编号，失败后可保留已完成片段。上游状态不明时标为待核对，不自动重复提交。排队中的任务可直接取消；已提交的网关任务会请求上游取消并等待确认，正在执行的配音暂不能取消。
- “配音与口型”是一个页面：选择视频、上传授权音色、填写文案，IndexTTS 合成后替换原音轨，或降低原音量混合；可选将新文案作为字幕叠加。字幕时间按语音时长估算，旧的硬字幕不会被擦除。音色归属当前用户，上传参考语音保留授权确认。音轨混合不能分离原人声，也不会改变人物口型。
- “数字人视频”整理为一个简单表单：可选人物首帧、场景和本人授权音色，输入最多 35 字，系统用 H3 生成短画面，并尝试用 IndexTTS 配音和叠加字幕。画面和配音没有口型同步，人物一致性不保证；配音或字幕失败时保留已生成的视频并显示未完成项。旧版演示形象与预设音色接口已停用。
- 视频解析支持上传或选取最长 120 秒的视频，提取语音并使用 FunASR 转写，抽取最多 5 帧交给 PPOCR 识别文字，再基于识别文本整理建议。它不能理解人物、动作、场景或镜头结构，也不支持解析平台分享链接；识别和整理结果需要核对。
- 阻止已确认的模拟支付、演示成片、固定分析、伪修复等操作继续报告成功；智能剪辑旧编辑器改为只读历史记录，不再展示虚构的初始时间线。脚本生成不覆盖旧分镜。停用启动时自动改写历史数据、回填作品和写入演示数据的操作。旧数据仍保留，来源不明的历史记录仍需核查。
- `/uploads` 和 `/api/files` 媒体访问需要登录态，服务端检查本人或团队素材、作品归属。上线前仍需完成其余路由的租户隔离、安全测试、认证与访问策略复核。

## 验证证据

- 对本机 ModelGate 提交一次真实文字视频任务：上游任务 `c29e5f1f-a934-4758-8872-6d8a6112cca9` 返回成功，成片经 FFprobe 检测为 **544×960、24 fps、4 秒、有音轨**。测试文件位于 `server/data/validation/h3-smoke-20261029/`，这是技术验证，不代表所有分辨率或所有模式均可稳定运行。
- 用该样片抽取的首尾帧进一步制作了 15 秒真实长视频：系统自动规划两段，先后完成上游任务 `8d747f50-45f6-42d6-8976-69bd66b05fe2`（首帧）和 `85a5ba36-8ede-4d72-a671-12a8b2ccb364`（首尾帧），再合成 **544×960、24 fps、15 秒、有音轨**的成片。抽帧显示相邻片段衔接的主体基本连续，但瓶身文字依然失真；这些只是单次样片观察，不代表质量稳定性已经达标。
- 更新后的结构化规划提示词已实际请求模型，分别成功返回两段和八段计划。后续使用合成商品首帧实际调度八次 H3，得到 544×960、24 fps、60 秒、有音轨的成片；瓶盖、光线和阴影存在变化，真实商品效果、耗时与可靠性仍需更多样本验证。详见 [未完成事项与真实验收台账](./08_未完成事项与真实验收台账.md)。
- 本机使用系统合成的测试音色，实际访问 `192.168.100.20:8092` 上传音色、生成语音并合成到上述视频。已从 IndexTTS 删除临时测试音色。真实用户音色和实际业务素材仍需验收。
- 在真实配音测试视频上烧录了中文字幕，并确认成片保留音轨。FunASR 实测返回整段语音的起止时间；该样本未提供可用于逐字对齐的时间，因此字幕同步仍按时长估算。
- 对该测试视频执行了真实语音转写和三帧 OCR：转写结果为“这是视频配音测试。”，抽帧 OCR 检出了部分瓶身文字但漏掉了画面字幕，表明识别仍可能漏字或误字。
- 核查视频抽帧时，尽管提示词要求无文字，商品瓶身仍出现不准确的英文字符；不能承诺模型会正确绘制商品标签。商品保真和文字合成需要图像编辑或后期合成能力。
- 隔离数据库与模拟网关测试覆盖四种 H3 输入、60 秒任务自动生成并拼接八段、长视频失败片段重试、失败退款、TTS 接口及音轨合成、数字人接入授权音色及失败提示、媒体权限、脚本原分镜保护、登录和端到端 API。其中 60 秒和数字人整条流程使用模拟网关验证，不能证明真实模型的效果和稳定性。真实首帧和首尾帧已在上述单次长视频测试中使用；单独尾帧模式、更多产品素材、长视频跨场景连续性与并发容量仍需受控验收。

## Linux 小规模部署

当前可用的是 **单实例 Node + SQLite 持久队列**，视频/图片与配音分别限流，默认各同时处理 1 个任务，适合小规模验证；不是 PostgreSQL、独立 worker 或多机部署。不要同时启动多个应用进程共用同一个数据库，因为当前启动恢复逻辑按单实例设计。需要多机、多进程和较高并发时，下一阶段再迁移 PostgreSQL 和独立 worker，并进行压测。

Docker 镜像不会包含本机 `.env`、数据库、上传文件或备份；数据库和上传文件放在独立持久卷中。默认应用端口只监听服务器本机的 `127.0.0.1:3001`，应由受控的 HTTPS 反向代理对外提供服务。可选搜索服务只在 Compose 内网，不默认对外开放。当前开发机没有 Docker，镜像尚未在 Linux 上构建验证。

在 Linux 的项目目录中，准备权限为 `600` 的部署环境文件，例如 `.env.deploy`，至少包含：

```dotenv
JWT_SECRET=替换为至少32字符的随机密钥
MODELGATE_BASE=你的网关完整基础地址
MODELGATE_API_KEY=你的网关密钥
INDEX_TTS_BASE_URL=http://192.168.100.20:8092
AI_TASK_CONCURRENCY=1
TTS_TASK_CONCURRENCY=1
```

IndexTTS 地址应只允许应用服务器访问，不能直接开放到公网；如 Linux 服务器不在同一内网，需配置受控的网络连接。后续接入统一网关时，应先确认其兼容相同的音色和语音接口，再调整服务地址。

```bash
docker compose --env-file .env.deploy up -d --build
docker compose --env-file .env.deploy ps
curl --fail http://127.0.0.1:3001/health
```

新数据库默认为空，不会自动创建示例账号。只有确认数据库没有用户时才执行一次初始化，密码输入不会显示在终端：

```bash
read -r -p '管理员账号: ' BOOTSTRAP_ADMIN_ACCOUNT
read -r -s -p '管理员密码（至少12位）: ' BOOTSTRAP_ADMIN_PASSWORD; echo
export BOOTSTRAP_ADMIN_ACCOUNT BOOTSTRAP_ADMIN_PASSWORD
docker compose --env-file .env.deploy run --rm \
  -e BOOTSTRAP_ADMIN_ACCOUNT -e BOOTSTRAP_ADMIN_PASSWORD \
  app node server/src/bootstrap-admin.js
unset BOOTSTRAP_ADMIN_ACCOUNT BOOTSTRAP_ADMIN_PASSWORD
```

有现有数据时，先取得 SQLite 一致性备份并完整保存上传目录，再规划卷迁移；不要运行 `seed.js`，它会删除业务表中的记录。迁移时也要保存独立的音色服务数据：平台数据库只保存音色映射，参考音色实际由 IndexTTS 服务持有。

本机实施前的数据库一致性备份和源码快照位于 `server/data/backups/`；该目录还包含实施前的环境配置备份，须按密钥保护。生产部署前应轮换已公开或默认账号密码、设置随机 JWT 密钥、配置 HTTPS，并完成登录限制、接口授权、数据隔离、任务恢复、备份恢复和容量测试。
