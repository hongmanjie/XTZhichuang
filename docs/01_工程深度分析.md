### 4.2 服务层（3 个核心文件）

#### `aiProviders.js`（653 行）— AI 供应商抽象层

统一封装 4 家供应商，全部采用 **ModelGate 优先 → 商用 API 降级** 的链路：

| 能力 | ModelGate 模型（优先） | 降级备选 |
|------|------------------------|----------|
| 对话（非流式/SSE） | Qwen3.6-35B-A3B-FP8 | 万界 qwen3.8-max |
| 文本向量（2048 维） | qwen3-vl-embedding-2b | SiliconFlow BAAI/bge-m3（1024 维） |
| 文本重排 | qwen3-vl-reranker-2b | SiliconFlow bge-reranker-v2-m3 |
| 语音转写 ASR | FunASR-Nano | — |
| 图片文字识别 OCR | PPOCR-v5-Server | — |
| 目标分割 SAM | SAM3-Image | — |
| 文生图 | Qwen-Image-2.1-Turbo | 即梦 / Qwen 商用 |
| 音视频生成 | MiniMax-H3 | 可灵 3.0 / 即梦 |

**设计亮点**：
- 所有 AI 产物（图片/视频）统一下载落盘到 `server/uploads/`，避免外链过期（`saveBase64ToUploads` / `downloadToUploads` / `mgDownload`）
- 每个请求带 `Idempotency-Key`（`crypto.randomUUID()`），防重复提交
- 异步模型统一走 `202 + task_id 轮询`（`mgTaskWait`，最长 240~300 次 × 5s）
- 流式降级策略严谨：`chatStream` 仅在 ModelGate **一个字都没产出**时才降级，避免内容重复（`aiProviders.js:602-618`）

#### `aiMock.js`（459 行）— AI 任务引擎

虽然文件名叫 Mock，实际是**真实任务编排器**：

```
createTask(ownerId, module, params, pointsCost)
   ├─ 生成任务编号（FK/MG/SP/SC/JX/SM/JJ 前缀 + 时间戳）
   ├─ 扣 AI 点数 + 写 consumption_logs
   └─ startTask()
        ├─ 置 status=running, progress=5
        ├─ 进度定时器：每 2500ms +1~4，爬升到 95% 后等待真实结果
        ├─ runRealTask() → ModelGate / 商用 API
        └─ catch → buildMockResult() 降级，标记 engine='mock' + fallbackReason
              └─ finishTask(): status=success, progress=100, 写入 works 表
```

7 个创作模块的点数定价：`replica 100 / factory 80 / studio 30 / materialField 60 / analysis 50 / human 70 / mix 40`

#### `esService.js`（326 行）— 检索服务

```
searchDocs(index, { keyword, filters, from, size, sort })
   ├─ BM25：multi_match，name^3/title^3 加权，fuzziness: AUTO
   ├─ kNN：dense_vector 语义召回（2048 维，cosine）
   ├─ 融合：bool.should + minimum_should_match: 1
   ├─ Rerank：ModelGate 重排前 50 条（仅首页且无 sort 时）
   └─ 返回 { total, mode, list }
```

索引管理较完善：自动创建、IK 缺失时降级 standard、向量维度变更时自动删除重建（`initES` 中的 `curDims !== EMBED_DIMS` 检测）。

## 六、关键设计评价

### 6.1 做得好的地方

1. **AI 降级链设计扎实**：ModelGate → 商用 API → 本地 Mock 三级降级，每级都有 try/catch 与日志，且流式降级避免了内容重复问题
2. **产物落盘策略**：所有 AI 生成的图片/视频统一下载到 `uploads/`，规避外链过期风险——这是工程上正确的取舍
3. **幂等性设计**：ModelGate 请求带 `Idempotency-Key`；支付接口有 `status==='paid'` 幂等判断（**实测验证：重复支付未重复加点**）
4. **索引自愈能力**：ES 索引自动创建、IK 缺失降级、向量维度变更自动重建
5. **上传文件名编码修复**：`Buffer.from(originalname, 'latin1').toString('utf8')` 正确解决中文文件名乱码
6. **统一响应格式**：`{code, data, message}` + `page()` 分页工具，前端拦截器统一解包，契约清晰
7. **性能表现优秀**：**实测 P50 5ms / P90 8ms / 并发 30 全部成功 / 吞吐 227 req/s**

### 6.2 架构层面的隐患

1. **README 与代码严重脱节**：文档停留在"纯 Mock"时代，未反映 ModelGate、语义检索、Rerank 等核心能力，会严重误导后续维护者
2. **租户隔离缺失**：后端 225 个端点中，大量查询/更新/删除不带 `owner_id` 条件。当前是单租户演示环境，一旦多用户真实使用即为越权漏洞
3. **两套异步任务实现并存**：`aiMock.js` 用 `taskTimers` Map 管理定时器；`creative.js` 用裸 `setTimeout`（6 处）且不清理，两者不一致
4. **Mock 与真实交织且无标记**：硬编码数据散落在前端常量与后端接口中，**全项目 grep `TODO|FIXME|mock|假数据` 命中 0 次**——所有假数据都伪装成正常代码，无法区分
5. **上传目录三处解析不一致**：`index.js` 与 `material.js` 依赖 `process.cwd()`，`aiProviders.js` 用 `path.resolve(__dirname,...)`。从仓库根目录启动会导致 multer 写入目录与静态服务目录不同，上传成功却 404
