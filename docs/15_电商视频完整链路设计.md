# 电商视频生成：从 ffmpeg 贴图到完整链路

> 2026-11-02。本文回答四个问题：商品图现在怎么来的、应该怎么做、官方怎么建议、超分放在哪。

## 一、现状：商品确实是 ffmpeg 贴上去的

`server/src/services/humanProduct.js` 第 88–96 行：

```js
const maxW = Math.floor(width * 0.42 / 2) * 2
const maxH = Math.floor(height * 0.28 / 2) * 2
const bottom = Math.floor(height * 0.06)
const filter = `[0:v]scale=...crop=...[bg];[1:v]crop=...scale=${maxW}:${maxH}...format=rgba[product];
                [bg][product]overlay=(W-w)/2:H-h-${bottom}:format=auto,format=rgb24[out]`
await runMedia(FFMPEG, ['-y','-filter_complex_threads','1','-i',background,'-i',inspected.file, ...])
```

拆开看就是：**人物背景图** + **商品抠图** → ffmpeg `overlay` 把商品盖在底部居中位置。

这不是图像生成，是图片编辑。所以三个后果：

1. 商品**贴边**（底部只留 6%），看起来"飘"在画面下沿
2. 商品**被裁**（高度 28% 时超出安全区）
3. **没有手、没有接触阴影**，商品和桌面之间没有物理关系

任务 52/53 的成片里，每一段的第 0 帧都是这张图，所以每次段首都会看到"杯子浮空"。
模型在段内会把杯子"拿起来"，段末在手里；下一段又回到浮空——这就是你看到的"中间又浮空一次"。

## 二、验证过的修复路径：贴图只是占位，i2i 负责融合

### 2.1 实验

拿任务 53 的第 0 帧（那张浮空图）做输入，送 Qwen-Image-2.1-Turbo 的 `i2i`：

```
输入：原合成图（杯子贴边浮空）+ 提示词（杯子放在桌面上、有接触阴影、完整入画）
输出：1280×720 重绘图
```

结果：**杯子完整入画、落在桌面上、杯底有柔和投影、光影统一、没有贴图痕迹**。

### 2.2 接口能力（实测，含坑）

| 项 | 结论 |
|---|---|
| 服务地址 | `http://192.168.12.43:9001`，容器 `lightx2v`，镜像含 `Qwen-Image-2.1-Turbo` |
| 支持 task | `t2i`（文生图）、`i2i`（图生图） |
| `i2i` 字段 | `image_path`（base64 或 URL）、`size`、`prompt` |
| **`i2i_denoise_strength` 不可用** | 配置里 `layered: true` 时该字段被移除，传了会报 `does not support request fields` |
| **同步接口不能带图** | `/v1/tasks/image/sync` 对带图请求一律 413，即使 body 只有 16KB |
| **异步接口可以** | `POST /v1/tasks/image/` 接受 base64，返回 task_id，轮询 `/v1/tasks/{id}/status` |
| 结果获取 | 必须传 `save_result_path`，否则 `/result` 返回 404；文件落在容器 `save_results/server_cache/outputs/` |
| 登录 | 192.168.12.43 可用 xtxk 账号，能 `docker cp` 取文件 |

### 2.3 限制

`i2i_denoise_strength` 不可用意味着**不能控制重绘强度**，每次都是全量重绘。
商品形状会有轻微变化（实测白色马克杯的杯身弧度和把手比例有差别）。

对"商品保真"要求极高的单子，需要：
- 降低重绘范围（只重绘商品以外的区域）→ 需要 mask，当前部署的 runner 不支持 `image_mask_path`
- 或者接受"接近但不完全一致"，靠后期核对

## 三、完整链路设计

```
① 商品事实提取        视觉模型读商品图 → 品类/主色/材质/可展示结构
                      （现有 describeProductImage 只输出 40 字，需要扩到结构化字段）

② 抠图                SAM3-Image（网关已有）或现有 cutout，输出商品 RGBA

③ 人物场景 t2i         Qwen-Image 生成"人物在桌前、桌面留空"的底图
                      提示词必须写：竖屏构图、桌面留出前景空间

④ 贴图占位（修正版）    ffmpeg 把商品放到桌面位置：
                      - 底部留 14–18%（不是 6%）
                      - 商品高度 20–24%，保证完整不裁
                      - 加柔和投影（正片叠底 + 高斯模糊）
                      这一步只求"位置对、大小对"，不求好看

⑤ i2i 融合            Qwen-Image i2i 重绘，统一光影、补接触面、修边缘
                      ← 关键新增，把占位图变成可用的锚定图

⑥ 锚定图确认           用户在页面上看到最终锚定图，不满意可重生成

⑦ H3 逐段生成          每段 i2av(锚定图)，anchorFirstFrame=true
                      段间动作由每段 prompt 决定

⑧ 口型同步            LatentSync，在 720P 上做（快）

⑨ 超分                SeedVR2-3B，整片超一次
⑩ 拼接 + ASR 对齐 + 字幕
```

## 四、超分：要做，但不是官方的做法

**官方有 In-Context Regeneration**：把 768p 输出和原始上下文一起回灌 H3-Base，重新生成 2K。
好处是文字、Logo 能在 2K 下清晰可辨；坏处是**该模块未开源，只能走官方 API**，而且耗时是 768p 的两倍以上。

我们只能用 **SeedVR2-3B 超分**（网关已有，直连 `192.168.100.20:10026`，按 20 点/秒计费）。

两者区别要说清楚：

| | H3 In-Context Regeneration | SeedVR2 超分 |
|---|---|---|
| 原理 | 重新生成，复用原始 prompt 和参考素材 | 放大 + 补细节 |
| 文字/Logo | 能恢复到可读 | 只会让已有像素更锐，糊的还是糊 |
| 速度 | 慢（数分钟） | 快（数十秒） |
| 我们能否用 | 不能（未开源） | 能 |

**所以超分放在口型之后、字幕之前**：
- 口型在 720P 做，速度快、显存小
- 整片超分一次，成本只花一次
- 字幕烧在超分后的高清片上，边缘更干净

如果先超分再做口型，LatentSync 要处理 2K 输入，慢且容易爆显存，不划算。

## 五、官方建议与 skill

### 5.1 电商该用哪种模式

第三方评测站转述官方建议（原文）：

> **Which mode is best for e-commerce video?** Use **first-frame or multimodal reference** when an approved product image must control identity. Use text-to-video for fictional concepts and early ideation.

所以是**两条路都可**：
- 商品必须严格保真 → 多模态参考（ref2av，需要 `transformer_ref` 权重）
- 商品只要"像" → 首帧（i2av，我们现在这条路）

我之前说"官方推荐 ref2av 做电商"是不准确的，官方给的是二选一。

### 5.2 多图参考的用法（官方原话）

> 素材顺序要有意义，并在提示词里点名用途

例如：`图片1 控制角色身份，图片2 控制商品外观，视频1 控制运镜节奏`。
不是把图一股脑塞进去让模型自己猜。

### 5.3 最贴合的官方 skill

`minimalist-product-ad-generator`，10 步流程，核心是：

```
商品图 → 产品事实 → 叙事脊柱（三选一）→ 英文文案 →
三张独立锚定照片 → 精确节拍分镜表 → 视频生成 → 配乐卡点 → 验收
```

四条硬规则：
1. **生视频时不要传原商品图**，只传锚定照片
2. **锚定照片不能当分镜用**，也不能按顺序直接拍成三段视频
3. **产品本体颜色是硬约束**，只允许改背景和光
4. **画面文案是视频内动效**，不是后期字幕

### 5.4 官方踩坑清单（可直接当验收标准）

- 产品剪影首尾是否一致
- 按钮、瓶盖、把手、接口是否保留
- 反光是否跟随表面而不是漂浮
- 手部解剖是否正确
- 液体是否遵守重力
- 镜头运动是否只做了一次
- 音效是否和可见接触同步

> Reject a clip when a structural error would require frame-by-frame repair.
> A slightly different background highlight may be acceptable; a changed product is not.

## 六、实施顺序

| 阶段 | 内容 | 依赖 | 预估 |
|---|---|---|---|
| **P0** | 撤掉商品场景的全段锚定（恢复只首段锚定），止住"每段浮空" | 无 | 半小时 |
| **P1** | 修贴图参数：底部 14–18%、完整不裁、加投影 | 无 | 半天 |
| **P2** | 接 i2i 融合：封装异步调用 + 取文件 + 失败兜底 | 12.43 可登录 | 1 天 |
| **P3** | 商品事实结构化提取（品类/主色/材质/结构） | 视觉模型 | 半天 |
| **P4** | 超分接入数字人链路（口型后、字幕前） | SeedVR2 已通 | 半天 |
| **P5** | 补 `transformer_ref` 权重，解锁真多图参考 | 下载数十 GB + 停机 2.5 分钟 | 待定 |

P0 是止血，P1+P2 是根治"浮空"，P4 才谈清晰度。

## 七、一句话总结

**现在的问题不是模型不行，是我们把"图片编辑"当成了"图像生成"。**
商品图不该用 ffmpeg 贴上去就完事，应该贴完再用图像模型重绘一遍，让光影和接触关系成立。
清晰度是另一件事，靠 SeedVR2 超分，和商品保真互不影响。
