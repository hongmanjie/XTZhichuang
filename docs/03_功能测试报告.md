## 五、🔴 P0 缺陷：ES 混合检索被 kNN 污染（搜索功能实质失效）

### 5.1 现象（决定性证据）

对素材库搜索接口 `/api/material/list` 发起不同关键词的查询：

| 关键词 | 应用接口返回 | 直连 ES 纯 BM25 返回 |
|--------|-------------|---------------------|
| `口红` | total=20（pageSize=20） | **6 条**，且相关性排序正确（score 13.70 / 12.18） |
| `面膜` | total=28 | — |
| `咖啡` | total=20 | — |
| `阿斯顿发斯蒂芬`（无意义） | **total=20** | **0 条** |
| `zzzzqqqq`（无意义） | **total=20** | **0 条** |
| `水电费第三方`（无意义） | **total=20** | **0 条** |

进一步用 `pageSize=5` 验证，返回内容如下：

```
搜索「zzzzqqqq无意义词」→ total=5，返回：
   - 26 精品咖啡豆特写   （与关键词毫无关系）
   - 25 冷萃咖啡冲泡     （与关键词毫无关系）
   - 30 精品咖啡豆特写
   - 29 冷萃咖啡冲泡
   - 20 护肤步骤图解

搜索「口红」→ total=6，返回：
   - 1 正红色口红特写  ✓ 正确
   - 8 口红礼盒开箱    ✓ 正确
   ...
```

**搜索任何内容（包括完全无意义的乱码），都会返回恰好 `pageSize` 条结果。**

爆款接口 `/api/hot/list`（无 sort 参数）同样受影响：

```
搜索「面膜」→ total=8，前 3 条：
   - 直男送礼指南！这份清单抄作业就行      ✗ 无关
   - 咖啡控必看！在家也能喝到星巴克同款    ✗ 无关
   - 面膜成分大起底！这些成分才值得买      ✓ 正确（却排第 3）

搜索「zzzzqqqq无意义词」→ total=5，返回 5 条无关视频
```

### 5.2 根因

`server/src/services/esService.js:238-255`：

```js
if (queryVector) {
  should.push({
    knn: { field: EMBED_FIELD, query_vector: queryVector, num_candidates: 100, k: knnK },
  })
}
...
minimum_should_match: should.length > 1 ? 1 : undefined,
```

其中 `const knnK = Math.min(60, from + size)`（第 216 行）。

**问题本质**：kNN 被放进 `bool.should` 子句，而 `minimum_should_match: 1` 意味着"命中任一子句即可"。但**向量检索的特性是"永远返回距离最近的 k 条"**，无论距离多远、与查询词是否相关。于是：

- kNN 无条件召回 `k = from + size` 条文档，恰好填满一页
- BM25 的真实命中被淹没在这批无关文档中
- 结果数量恒等于 `pageSize`，与关键词相关性完全脱钩

**叠加问题**：`material.js:92` 传入 `sort: [{ created_at: 'desc' }]`，导致：
1. ES 忽略相关性评分 → 前端拿到 `_score: null`
2. `esService.js:265` 的 Rerank 条件 `!sort` 不满足 → **Rerank 精排被完全旁路**

**结论**：素材库搜索目前的实际行为是「按创建时间倒序返回前 N 条」，关键词只影响"是否出现在候选集"，不影响排序；而 kNN 又保证了候选集总是满的。

### 5.3 影响

| 影响面 | 说明 |
|--------|------|
| 功能 | 资产库搜索、爆款搜索、脚本搜索**全部失效**，用户无法靠关键词找到目标 |
| 体验 | 搜索结果数量恒定、内容无关，用户会认为"搜索是坏的" |
| 演示 | 这是原站复刻的核心卖点之一（README 单独设"Elasticsearch 检索"章节），当前状态会直接暴露 |

### 5.4 修复方向（供参考，本次未改代码）

1. **kNN 与 BM25 分离**：kNN 不应作为 `should` 无条件召回。建议改为两路召回后在应用层做 RRF（Reciprocal Rank Fusion）融合，或给 kNN 加 `boost` 并调高 `minimum_should_match`。
2. **加相关性门槛**：kNN 结果应按 cosine 相似度设阈值过滤，丢弃低分结果。
3. **修正 `k` 的取值**：`k = from + size` 应改为固定超召回（如 `min(50, ...)`），再经 Rerank 截断到 `size`。
4. **重新审视 `sort` 与 Rerank 的互斥**：需要按时间排序时，应先做相关性召回+Rerank，再在结果内排序；或让 Rerank 与 sort 可共存。
5. **回归验证**：修复后应验证"无意义关键词返回 0 条"、"口红返回 6 条且相关项排前"。
